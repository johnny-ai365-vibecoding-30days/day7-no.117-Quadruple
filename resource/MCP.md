# MCP

# Understanding Model Context Protocol (MCP)

## 一、簡介 MCP

MCP（Model Context Protocol）是一套專門用於大型語言模型（LLM）與外部工具、服務互動的應用層協議。想像 HTTP（定義瀏覽器與伺服器之間請求／回應格式）與 USB-C（統一各種裝置連接介面）的結合：MCP 就是為 LLM 與外部工具互動量身打造的「應用層協議」。

只要按照這份協議實作，不論是模型端（Client）或工具端（Server），都能無痛加入 MCP 生態系。MCP 定義了「工具清單查詢」、「函式呼叫」、「結果回傳」等流程與 JSON 格式，使不同廠商、不同模型都能用同一份合約進行 Function Calling，將整合成本降至最低。

---

## 二、源由：為何要有 MCP？

1. **Function Calling 差異帶來的困境**
    - 各家 LLM 平台對呼叫工具的 JSON 結構、API 路徑、欄位命名都可能不同，開發者要一一適配，容易出錯且維護成本高。
2. **MCP 的使命**
    - 由 Anthropic 於 2024 年底提出，目的是在「inference‑time」階段，為模型與工具之間架起一座「語意契約」的橋樑。只要各方遵守這份開放標準，就能快速互通、無痛更新。

---

## 三、協定核心：HOST、CLIENT、SERVER

MCP 規範將整個互動角色拆成三大角色，各自必須實作的功能如下：

| 角色 | 職責 | 必要功能 |
| --- | --- | --- |
| **HOST** | 總控中心，管理多組 Client ↔ Server 的通道與事件路由 | 啟動／關閉 Client；串接使用者輸入與模型輸出；監控所有通道狀態 |
| **CLIENT** | 代表模型一端，負責根據模型輸出啟動工具呼叫，並回傳結果給模型 | `listTools()` 列出可用工具；`invoke(method, params)` 呼叫工具；`onResult()` 處理回傳 |
| **SERVER** | 代表工具或資源一端，接收 Client 呼叫並執行實際邏輯（如資料庫查詢） | 暴露 tool 清單；驗證輸入參數；執行業務邏輯；以 JSON 回傳結果 |

## 四、近期發展：MCP 的現況

- **2024 Q4**：Anthropic 正式發佈 MCP 規範初稿，開源文件與 GitHub Repository 首度公開。
- **2025 Q1**：OpenAI、Google DeepMind、各大開源社群陸續宣告支援 MCP 格式；部分模型透過 fine‑tuning 或提示工程，已能正確輸出符合 MCP JSON。
- **MCP 生態平台湧現**：mcp.so 提供線上測試與管理環境，mcp market 打造微服務交易與評價市集，mcpserverhub 收錄各家 MCP Server 實作範例，促進開發者分享與工具發現，加速生態成長。
- **目前挑戰**：生態尚未完全成熟，工具封裝範例、社群驗證測試案例仍在持續增補中。

---

## 五、3 月底更新：為了改善什麼？

2025 年 3 月底，Anthropic 推出了 MCP v1.1 更新，重點包括：

1. **增強錯誤回報結構**：定義更細緻的 error code，便於模型與開發者快速定位問題。
2. **streaming 支援優化**：加入分段回傳（chunked response）標記，提升大型結果處理效率。
3. **tool metadata 擴充**：允許在清單中註明工具的版本、限制與授權資訊，強化安全性與可管理性。

## 六、願景與挑戰

- **願景**
    1. **生態共榮**：希望成為 LLM ↔ 工具／服務 互通的事實標準，降低跨廠商整合門檻。
    2. **工具市場化**：任何人都能依 MCP 寫出「即插即用」的微服務，模型呼叫如同插上隨插即用的模組。
- **挑戰**
    1. **標準採用率**：需要更多領域龍頭（如企業級 SaaS、開源框架）納入，才能真正形塑生態。
    2. **安全與授權**：呼叫外部工具時如何保障資料隱私、權限管理，以及防止濫用，是實務必解難題。
    3. **錯誤處理一致性**：各 Server 實作的容錯行為、重試策略若不一致，仍可能導致使用者困惑。

---

## 七、AI 市場展望：MCP 帶來的可能性

1. **快速拼裝 AI 應用**：開發者只要組合不同 MCP‑compatible 工具，就能快速打造客製化聊天機器人、智慧助理、資料分析管道。
2. **跨模型協作**：不同廠商的 LLM（如 Claude、GPT、Gemini）都能共用同一組工具，未來或許可實現「模型融合」的強大場景。
3. **生態開放商店**：類似 App Store 的「MCP Market」，上架各種微服務，使用者根據需求即插即用，形成真正的工具經濟。

> MCP 正在改變我們與 AI 互動的方式：從「自家專屬」到「生態共用」，從「零散開發」到「標準化組裝」，未來只要一套協議，就能串聯起無限可能。
