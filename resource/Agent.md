# Agent

# Understanding AI Agents

## 一、什麼是 Agent？

在軟體工程裡，**Agent** 就像是一位「數位助理」，能夠在授權範圍內，依照預先設定的流程或規則，自動處理特定任務。

> 例如：定時檢查郵件，若主旨符合條件就分析信件內容，然後把結果存進資料庫──這整個自動化流程，就可以稱為一個郵件處理 Agent。
> 

簡短演進：

- 1959 年 Oliver Selfridge 的「Pandemonium 模式」裡，每個 demon 其實就是早期的感知 Agent 。
- 1990 年代，FIPA 組織開始制定多 Agent 系統標準，並出現 KQML、JADE、Zeus 等平台。
- 近年低程式碼/無程式碼工具（Zapier、n8n、Coze）也都在延續這個概念。

---

## 二、Agent 的定義

只要符合以下要件，就可以算是「傳統 Agent」：

1. **有限／可控的流程範圍**
    - 所有步驟、分支條件與完成標準都事先定義。
2. **事件式或定時式觸發**
    - 由外部事件（Webhook、MQ 訊息）或定時排程（Cron）啟動。
3. **整合多個異構系統**
    - 透過 API、Webhook、資料庫連線等，把不同服務串接在一起。

### 範例系統

- **Cron Job**：最經典的排程 Agent；
- **Zapier / n8n / Coze**：圖形化工作流程編排；
- **Enterprise BDI 平台（如 JACK）**：用「信念‑欲望‑意圖」建模複雜業務流程。

---

## 三、什麼是 AI Agent？

當 Agent 加入了**大型語言模型（LLM）**作為「智慧核心」後，就成為 **AI Agent**。它不只照著寫死的流程走，而是能：

- **以自然語言理解需求**
- **動態拆解高階目標**，並自動產生子任務
- **即時決定要呼叫哪些工具或服務**
- **根據回饋自行調整流程**

### AI Agent 舉例

- **Siri / Google Now / Alexa**：消費端語音助理，能解析人類指令並完成多步任務。
- **AutoGPT / BabyAGI**：用 GPT-4 API 自主規劃、執行並反覆迭代子任務。
- **LangChain Agents**：提供「Chains」「Agents」「Tools」等抽象，讓開發者快速打造自訂 AI Agent。
- **DeepResearch（ChatGPT 功能）**：根據使用者的「研究目標」，自動搜尋、摘要、交叉驗證並產出報告。

---

## 四、AI Agent 的定義

簡化來說，AI Agent 必須具備：

1. **自主規劃**：從高階需求自動拆解成可執行的子任務。
2. **動態整合**：執行時決定並呼叫最合適的工具／服務。
3. **事件或需求驅動**：以自然語言指令或定時排程為觸發。
4. **自我監控與改錯**：遇到失敗時可進行例外處理或重新規劃。

---

## 五、傳統 Agent vs. AI Agent：相似與差異

| 面向 | 傳統 Agent | AI Agent |
| --- | --- | --- |
| 流程控制 | 完全由人事先定義 | 部分或全部由 AI 自主擬定 |
| 觸發方式 | 事件／定時 | 事件／定時＋自然語言指令 |
| 工具整合 | 固定串接、靜態 | 動態選擇、智慧化 |
| 任務拆解 | 流程設計者（人）掌握 | AI 根據目標自動拆解 |
| 適用場景 | 重複性、結構化流程 | 高階目標、多元任務、需彈性調整時 |

---

### 結語

傳統 Agent 與 AI Agent 的本質都在「自動化任務、串接異構系統」，但 AI Agent 更進一步從「流程執行者」變身為「流程設計者兼執行者」，能夠自行規劃、動態選擇工具，並在執行中不斷優化。隨著 Function Calling 與 LLM 的結合，我們正進入「讓機器用人類思路思考」的新世代 Agent 時代。
